## ✅ แก้แล้ว 19/11 (รอบ 1 — ข้อมูลผิด/หาย/ขอบเขต)

1. **BBS อ่านผลสังเกตเกินเพดาน 1,000 แถว** → `fetchAllPages` + บอกบนจอเมื่อโหลดไม่ครบ
2. **BBS ปิดข้อตกลงไม่ครบแต่ขึ้น "บันทึกแล้ว"** → อ่านค่าคืนของ `checkWriteRows` · ไม่ครบ = ค้างหน้าต่างไว้
3. **Poka-Yoke ลบอุปกรณ์ = ผลทดสอบย้อนหลังหาย** (FK cascade) → มีประวัติ = เสนอปิดใช้งานแทน ·
   นับประวัติไม่ได้ = ไม่ลบ · migration `20261119_pokayoke_checks_fk_restrict.sql` (Main) เปลี่ยน FK เป็น `restrict`
   · ⚠️ สิทธิ์ RLS ของ Poka-Yoke **ใน DB จริงเป็น `has_perm` แล้ว** (migration ตั้งต้นเขียน `using(true)` แต่ถูกแก้ทีหลัง)
4. **ชั้น ③ ใน Poka-Yoke + BBS** — วัดกับข้อมูลจริงก่อนใส่ด่าน (รัน `canWriteLine` จริงกับผังองค์กร + CC จริง):
   BBS 46 คู่ (ผู้บันทึก × ไลน์) · Poka-Yoke 13 คู่ = **ผ่านหมด ไม่มีใครถูกบล็อก**
   · Poka-Yoke แก้ทะเบียนเช็ค 2 ฝั่ง (ไลน์เดิมของแถว + ไลน์ปลายทาง)
5. **% ความครบของ BBS นับวันหยุด/วันไลน์ไม่เดินเป็นตัวหาร** → ตัดสินรายวันด้วย `checkDayState`
   (ไลน์เดิน = มีกะเปิดในครอบครัวไลน์ · BBS ไม่แยกกะ) · บอกบนจอว่าไม่นับกี่วัน + ❔ ไม่รู้กี่วัน

## ⏸️ ค้างไว้ — ต้องให้ user ตัดสิน (อย่าทำเอง)

- **ข้อ 7 — `ppe_check_items.employee_id` cascade**: ทั้งฐานมี **16 ตาราง** ที่ cascade จาก `employees`
  (รวม `daily_production_logs` · `bbs_observations`) = ดีไซน์ทั้งระบบ "ลบพนักงาน = ล้างทุกอย่าง" ·
  โค้ดฝั่ง client ไม่มีที่ลบ `employees` เลย (ใช้ `is_active`) · เปลี่ยนตัวเดียวเป็น restrict = ตารางเดียวที่ขวางการลบ
  ⇒ เป็นนโยบายทั้งระบบ ไม่ใช่บั๊กของ PPE
- **ชั้น ③ ใน `/checkin`** (เช็คชื่อ + PPE + จองรถ OT บันทึกพร้อมกันทั้งจอ · มีคนยืมข้ามไลน์ `line_helpers`)
  — blast radius = เปิดกะทั้งโรงงาน ต้องวัดกับข้อมูลจริง + ตัดสินเรื่องคนยืมก่อน
- **PPE 2 ระบบซ้อน** (`/checkin` 3 ช่องเก่า vs ทะเบียน `ppe_items`) · ชุดคำตอบรวมชุดเดียวไหม · NG → งานติดตาม
- **Poka-Yoke อุปกรณ์ที่ปิดใช้งานแล้วไม่มีที่ให้เห็น/เปิดกลับบนจอ** (จอแสดงเฉพาะ `is_active` — มีมาก่อน 19/11)
